## 01 基本信息

### 作品名称（3 选 1）

**推荐：麦麦搭配助手 · 一句话配好三人餐**

备选：
- 麦当劳智能点餐推荐助手
- 麦麦搭配助手：口语点餐 × 官方菜单 × 四维权衡

### 一句话介绍

**说清人数、预算、忌口和想吃什么，我从麦当劳当前时段的官方菜单里，给你配出三种吃法。**

（备选：「不是聊天机器人——你给一句自然语言，我给出三套能直接照着下单的方案，每一分钱和每一大卡都有官方出处。」）

### 作品说明（使用方式 / 亮点 / 实现思路）

**使用方式**

打开页面，在输入框随口说一句就行，四类信息顺序随意、不用凑齐：

- 几人：3个人 / 我们仨 / 四个人
- 预算：100块以内 / 80到120 / 预算不限
- 忌口：不吃辣 / 忌牛肉 / 不要乳制品
- 想吃：我要吃炸鸡 / 来一份薯饼 / 想吃麦辣鸡腿堡

点「给我搭三份」，出来省钱聚餐 / 低卡高蛋白 / 新品尝鲜三版。顶部「🧭 我理解成了…」会把解析结果复述一遍，一眼能确认它有没有听错；缺了哪类信息，下方还会给「＋几人 / ＋预算 / ＋忌口 / ＋想吃」的补全提示，点一下就追加到输入框。

**亮点**

1. **口语真的能接住**。修过一个真 bug：动词正则会把「吃」「个」这些缓冲词一起吞进去，导致用户说「想吃炸鸡」，三份方案里一道炸鸡都没有，还一直推汉堡。现在「我要吃炸鸡」「我想吃炸鸡和薯饼」「咱们俩」这些说法都能正确解析，一句话点两个菜会各收各的。
2. **套餐能拆，但不撒谎**。麦当劳官方 MCP 根本没有「套餐改配」接口，所以「去掉薯条的汉堡套餐」买不到。做法是：把想要的子项按官方单点价另买，跟买整份进同一个打分池比价——谁划算谁上，不预设「拆开一定更省」。每个方案都写明这条边界。
3. **四维权衡摆到台面上**：价格 / 热量 / 蛋白质 / 口味匹配。官方没给数据的维度一律写「官方未提供」，不画 0、不估算。
4. **多人用券不撒谎**：券是绑在**下单账号**上的，不跟人走——所以不做「给每个人分一张券」这种假动作。正确做法是：看账号里有几张值得用的券，就把这桌菜拆成几单（每单限用一张），由号主一个人下这几单；人只用来算「谁该转多少钱给号主」。一人点完所有人的话，就只下一单、不分账。每张券的去向进账本（已用 / 未排上 / 不适用 / 无收益）。官方不返回券 code，券收益恒标记为预演值，不装成真省。
5. **可解释**：解析复述、冲突提示、来源角标（整份套餐 / 单独点 / 套餐子项转单点），全程不黑箱。
6. **在线 / 离线同一套页面，一键切换**。顶部按钮实时显示当前模式：在线时「在线 MCP · 可切离线」带绿点，点一下跳到 `?offline=1` 走快照；离线时点开是配置教程（能力对照表 + 三步快速配置 + 四类常见报错 + 安全边界），探测到本机服务就直接连过去。评委不用配环境也能看，配了 Token 的人看到的是实时数据。
7. **在线模式下券是真的实时**。官方 `available-coupons` 回的是 markdown，页面解析成券卡并在每张券上标「（实时）」；拉不到就回落到随包快照，并在页面写明「拉取失败，当前展示的是快照」——不把旧数据装成新的。

**实现思路**

- 解析走规则流水线（归一化 → 实体召回 → 槽位填充 → 冲突消解 → 置信兜底），不调 LLM：离线可跑、可解释、Token 不进前端。
- 数据与引擎分层：`data/*.js` 是官方 MCP 抓下来的时段快照，`engine.js` 负责打分与优化，`service.js` 是契约层，`app.js` 只负责渲染。
- 双模式：双击 `index.html`（file://，纯离线快照，零网络请求）；或 `python server.py` 起本机后端，实时调官方 MCP 算价（Token 只留在本机，绝不进前端）。两种模式是**同一份前端**，靠 `?offline=1` 切换，页面会明确告诉你当前数据是实时还是快照。
- 在线与离线的差别写在界面上，不靠用户猜：菜单/门店/价格/售罄/券 走官方接口时标「在线 MCP」与「（实时）」；离线一律标「离线预演」，券收益标「估算」。
- 边界写死在代码与文案里：不调用下单接口、官方无数据写「官方未提供」、离线标「离线预演」而非绿色「已校验」。
