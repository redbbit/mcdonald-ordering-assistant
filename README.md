# 麦当劳智能点餐推荐助手

> 一句话：**对着它说人话（"3 个人、150 块以内、有人减肥、不吃辣"），它用麦当劳官方 MCP 的真实菜单、真实价格、真实营养数据，给你三套可以马上下单的方案。**

## 两种跑法，都能用

| | 怎么跑 | 用到的数据 | 适合谁 |
|---|---|---|---|
| **离线模式** | 双击 `index.html` | 构建期落盘的快照 + 本地图片 | 评委、演示、断网——**不用起服务，不用联网** |
| **在线模式** | `python server.py` 后开 `http://127.0.0.1:4317/` | 运行时真调 MCP | 要出示"此刻真的调了官方接口"的证据 |

两条路共用同一套算法和 UI，区别只在数据从哪来。页面会自动判断：起服务就在线，没起就离线，**不会卡住也不会报错**。

---

## 为什么这么设计

| 需求 | 做法 | 为什么值得知道 |
|---|---|---|
| 会场网络不可控 | 快照在本地，双击即开 | 断网演示不翻车，这是主演示路径 |
| 数据必须是真的 | 122 款商品每款都跑过官方 `calculate-price`；在线模式还会当场再算一次 | 不是估算、不是编的，底气来自调用记录 |
| Token 不能泄露 | **浏览器永远不直连 MCP**，只跟本机服务说话，Token 只活在那个进程里 | 前端直连必然暴露 Token，所以中间必须隔一层 |
| 浏览器不能连外网 | 安检器禁止任何外部域名请求目标 | 不是"不联网"，是**"只连本机，绝不连外网"** |
| 不许真下单 | 代码里没有下单入口，`create-order` 由安检器禁止 | 作品止于"算这一单"，下单交给官方小程序 |

**架构一句话**：`浏览器 → （可选）本机服务 → MCP`；不起服务时`浏览器 → 本地快照`。

```
                                  ┌─ 在线：server.py（持 Token）──► mcp.mcd.cn
                                  │        ↑ 127.0.0.1:4317，浏览器只到本机
index.html ← app.js ← service.js ─┤
                                  └─ 离线：data/menu_data*.js + img/（构建期真调 MCP 落盘）
                                           ↑ 不起服务时走这条，零网络请求
```

## 双模式：离线不假装，在线不偷懒

**这是本项目最核心的一条自律：任何不是此刻真的从官方拿到的数字，都必须标出来。**

| | 离线模式 | 在线模式 |
|---|---|---|
| 价格 | 快照价，**标「预演校验」黄色** | 官方 `calculate-price` 实算，绿色「已校验」 |
| 库存 | 一律 `unknown`，显示灰色"以门店实际为准" | 真探测，60006 才显示红色"已售罄" |
| 券收益 | 券面标题规则估算，**恒标 `simulated: true`** | **同为估算**——官方 `available-coupons` 不返回券 code，无法代入算价；但在线可对每张小单真调 `calculate-price` 拿真实价格与配送费 |
| 分账 | 基于快照价，**标 `simulated: true`** | 基于实付 |
| 配送费 | 离线快照只有到店价，外送侧一律「未估算」 | 按官方返回计入，外送算价自动带 orderType=2 + 地址 beCode |
| 券的堂食/外送适用性 | 依据券面标题文字判断，账本逐行标注 | 同为标题判断——官方 `query-store-coupons` 才按订单类型返回可用券，前端未调用该接口，不装成已校验 |

**离线绝不显示红色"售罄"** —— 红色会让评委以为我们真的探测到了，那就是伪造。同理，离线也绝不出现绿色"已校验"。这些约束不是口头承诺，`tools/test_adapter.js` 的 50 项断言里锁死了。

## 它能干什么

**左：对话式提问。** 预算可以是区间甚至"无限"——`150 以内`、`100-200`、`不吃辣`、`3 个人`、`高蛋白`、目标随便填一句话。

**右：滚动活动板。** 麦当劳官方活动日历 + 优惠券，图片全是官方 CDN 原图。

**中间：固定三版方案，每版都能展开看账。**

| 方案 | 思路 |
|---|---|
| 省钱聚餐版 | 在预算内把人均压到最低，优先用券和套餐差价 |
| 低卡高蛋白版 | 按"蛋白质 / 热量"密度排序，砍掉高热量低营养单品 |
| 新品活动尝鲜版 | 只挑 `tags` 里带官方"上新"标记的商品 |

每个方案下两个按钮：**「这顿的热量」** 展开逐项热量明细 + 人均；**「营养成分」** 展开蛋白质/脂肪/碳水/钠。官方没给的数据**显示"官方未提供"**，绝不自己估算。

**时段切换**：下午茶（15:17）/ 夜市（18:21）/ 宵夜（22:21）三套真实菜单快照，各自在对应时段内实抓。同一句"3 人 150 以内"，下午茶算出 **¥84.7**，夜市算出 **¥93.8**——菜单和价格本来就不同，不是随机抖动。

> 有一处如实说明：这家 24 小时店的**下午茶和宵夜菜单完全一致**（都是 122 款、价格相同），只有夜市那份不同（120 款）。我们抓到什么就显示什么，不会为了让三个时段"看起来有差异"而去改动数据。

**分账**：三种口径（人均等分 / 按谁点了什么 / 按权重），统一用最大余额法落分，保证各份之和严格等于总额（100 元三人均分不会出现 33.33×3=99.99 差一分）。

**多人拆单 · 分人用券**：两种点餐方式任选——**各自点**（拆成每人一张小单、各自配一张券）或**一人点完所有人**（省事：全单一张券，最大余额法人均分摊，Σ各人严格等于全单应付）。两条路子并排给结论：哪条省钱、差多少、各自点多付几次配送费。用餐方式（到店/堂食 vs 外送/麦乐送）单独可选：在线算价按官方 `orderType=1/2` 走，外送自动解析地址 beCode（拿不到就明说，不编）；未说明时不默认堂食。**每张券的去向记进「券账本」**：用出 / 没排上（附本单最多可省多少）/ 不适用（附原因）/ 无收益，一行一张，诚实到每一张。券收益按券面规则估算（官方不返券 code，离线在线一致），每单最多一张（官方未提供叠加规则，不假设能叠）。在线模式下每张拆单会真调一次 `calculate-price`，展示真实价格与配送费。

**特色模式**：说「哥/姐有钱，就喜欢单点」触发**单点畅吃**——候选池排除套餐及品名带「套餐/组合/桶/分享餐/件套」的菜（官方分类把部分套装归在 main，品名兜底）；说「宵夜」触发**宵夜模式**（偏好加权，非官方分类）。套餐想拆开单点也可以：「想要开心亲子双人餐里的板烧」会按单点计入并标注「不享受套餐组合价」。套餐值不值不只看价格：官方子项单点价重算 + 省额加权 + 热量营养交给目标权重，判断标准多元。

**输入冲突不装傻**：输入框写「3 个人」而人数控件选的是 2、文本预算和控件预算不一致、说想吃某道菜但它正好在忌口清单里——三种情况都会检出，弹提示说明「谁生效了、为什么」，并把控件同步回实际生效值（文本 > 控件 > 默认）。忌口安全优先，被挡掉的点名菜会如实说「已不加入方案」，不静默丢弃。

**点名菜一定出现**：「想吃巨无霸」会校验成菜单里的真实菜品（带规格层级惩罚：「麦辣鸡腿堡」对上的是 ¥22.5 的单品，不是 ¥28 的四件套），预算里给它预留位置，尽量塞进每一版；塞不进去（超预算 / 忌口挡住 / 菜单里没有）会进「没能落实」清单，说明原因。

**套餐 vs 散件**：含套餐的方案会按官方子项单点价重算——「安格斯厚牛堡四件套 ¥37 vs 子项单点合计 ¥45，省 ¥8」直接写在菜品上和方案标签里。子项只对上一部分价时，省额标注为下限（「省 ¥8 起」），不装全知。

**目标没听懂也不吓人**：说的话匹配不上内置目标时，不再弹「没能匹配到内置目标」，而是「先按『均衡就好』理解（670 kcal/人）」+ 一排可点的目标示例，点一下就按新目标重配。

## 跑起来

```bash
# 离线演示（零依赖，推荐先看这个）
双击 index.html

# 在线演示（真调 MCP，需本机 MCP 可用）
python server.py                # 然后浏览器打开 http://127.0.0.1:4317/

# 自检
node tools/test_engine.js      # 引擎自检：目标匹配 / 套餐对比 / 拆单用券 / 点名菜 / 用餐方式 / 特色模式
node tools/test_service.js     # 398 项断言（含券账本全量、合单人均 Σ 校验）
node tools/test_adapter.js     # 50 项：双模式与分账，离线三不伪造
node tools/test_slots.js       # 14 项：多时段是真独立数据
node tools/test_assign_ui.js   # 13 项：拆单结果渲染回归（split / together / 无账本）
node tools/check_release.js    # 发布安检：Token / 外网域名 / 图片

# 重新拉真实数据（需本机 MCP 可用）
python tools/build_data.py                 # 当前时段菜单
python tools/build_data.py --slot latenight  # 指定时段
python tools/build_campaigns.py            # 活动日历
python tools/build_evidence.py             # 生成 EVIDENCE.md 调用证据
```
