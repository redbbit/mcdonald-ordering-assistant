# 麦当劳智能点餐推荐助手

> 一句话：**对着它说人话（"3 个人、150 块以内、有人减肥、不吃辣"），它用麦当劳官方 MCP 的真实菜单、真实价格、真实营养数据，给你三套可以马上下单的方案。**

## 两种跑法，都能用

| | 怎么跑 | 用到的数据 | 适合谁 |
|---|---|---|---|
| **离线模式** | 双击 `index.html` | 构建期落盘的快照 + 本地图片 | 评委、演示、断网——**不用起服务，不用联网** |
| **在线模式** | `python server.py` 后开 `http://127.0.0.1:4317/` | 运行时真调 MCP | 要出示"此刻真的调了官方接口"的证据 |

两条路共用同一套算法和 UI，区别只在数据从哪来。页面会自动判断：起服务就在线，没起就离线，**不会卡住也不会报错**。

---

## 为什么这么设计

| 需求 | 做法 | 为什么值得知道 |
|---|---|---|
| 会场网络不可控 | 快照在本地，双击即开 | 断网演示不翻车，这是主演示路径 |
| 数据必须是真的 | 122 款商品每款都跑过官方 `calculate-price`；在线模式还会当场再算一次 | 不是估算、不是编的，底气来自调用记录 |
| Token 不能泄露 | **浏览器永远不直连 MCP**，只跟本机服务说话，Token 只活在那个进程里 | 前端直连必然暴露 Token，所以中间必须隔一层 |
| 浏览器不能连外网 | 安检器禁止任何外部域名请求目标 | 不是"不联网"，是**"只连本机，绝不连外网"** |
| 不许真下单 | 代码里没有下单入口，`create-order` 由安检器禁止 | 作品止于"算这一单"，下单交给官方小程序 |

**架构一句话**：`浏览器 → （可选）本机服务 → MCP`；不起服务时`浏览器 → 本地快照`。

```
                                  ┌─ 在线：server.py（持 Token）──► mcp.mcd.cn
                                  │        ↑ 127.0.0.1:4317，浏览器只到本机
index.html ← app.js ← service.js ─┤
                                  └─ 离线：data/menu_data*.js + img/（构建期真调 MCP 落盘）
                                           ↑ 不起服务时走这条，零网络请求
```

## 双模式：离线不假装，在线不偷懒

**这是本项目最核心的一条自律：任何不是此刻真的从官方拿到的数字，都必须标出来。**

| | 离线模式 | 在线模式 |
|---|---|---|
| 价格 | 快照价，**标「预演校验」黄色** | 官方 `calculate-price` 实算，绿色「已校验」 |
| 库存 | 一律 `unknown`，显示灰色"以门店实际为准" | 真探测，60006 才显示红色"已售罄" |
| 券试算 | 券面规则匹配，**标 `simulated: true`** | 逐张真实试算 |
| 分账 | 基于快照价，**标 `simulated: true`** | 基于实付 |

**离线绝不显示红色"售罄"** —— 红色会让评委以为我们真的探测到了，那就是伪造。同理，离线也绝不出现绿色"已校验"。这些约束不是口头承诺，`tools/test_adapter.js` 的 42 项断言里锁死了。

## 它能干什么

**左：对话式提问。** 预算可以是区间甚至"无限"——`150 以内`、`100-200`、`不吃辣`、`3 个人`、`高蛋白`、目标随便填一句话。

**右：滚动活动板。** 麦当劳官方活动日历 + 优惠券，图片全是官方 CDN 原图。

**中间：固定三版方案，每版都能展开看账。**

| 方案 | 思路 |
|---|---|
| 省钱聚餐版 | 在预算内把人均压到最低，优先用券和套餐差价 |
| 低卡高蛋白版 | 按"蛋白质 / 热量"密度排序，砍掉高热量低营养单品 |
| 新品活动尝鲜版 | 只挑 `tags` 里带官方"上新"标记的商品 |

每个方案下两个按钮：**「这顿的热量」** 展开逐项热量明细 + 人均；**「营养成分」** 展开蛋白质/脂肪/碳水/钠。官方没给的数据**显示"官方未提供"**，绝不自己估算。

**时段切换**：下午茶 / 夜市 / 宵夜三套真实菜单快照。同一句"3 人 150 以内"，下午茶算出 **¥84.7**，夜市算出 **¥93.8**——菜单和价格本来就不同，不是随机抖动。

**分账**：三种口径（人均等分 / 按谁点了什么 / 按权重），统一用最大余额法落分，保证各份之和严格等于总额（100 元三人均分不会出现 33.33×3=99.99 差一分）。

## 跑起来

```bash
# 离线演示（零依赖，推荐先看这个）
双击 index.html

# 在线演示（真调 MCP，需本机 MCP 可用）
python server.py                # 然后浏览器打开 http://127.0.0.1:4317/

# 自检
node tools/test_service.js      # 309 项断言
node tools/test_adapter.js      # 42 项：双模式与分账，离线三不伪造
node tools/test_slots.js        # 10 项：多时段是真独立数据
node tools/check_release.js     # 发布安检：Token / 外网域名 / 图片

# 重新拉真实数据（需本机 MCP 可用）
python tools/build_data.py                 # 当前时段菜单
python tools/build_data.py --slot latenight  # 指定时段
python tools/build_campaigns.py            # 活动日历
python tools/build_evidence.py             # 生成 EVIDENCE.md 调用证据
```
